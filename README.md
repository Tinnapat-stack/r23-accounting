## ติดตั้งครั้งแรก

1. สร้างโปรเจ็กต์ที่ [supabase.com](https://supabase.com) (แพ็กเกจฟรีพอ) เลือก region สิงคโปร์
2. ไปที่ **SQL Editor** วางเนื้อหาไฟล์ใน `supabase/migrations/` ทีละไฟล์ตามลำดับเลข (0001 → 0002 → 0003 → 0004) แล้วกด Run
3. ไปที่ **Authentication → Sign In / Providers → Email**: เปิด Email และเปิด **Confirm email**
4. ไปที่ **Authentication → URL Configuration**: ตั้ง Site URL และ Redirect URLs เป็นที่อยู่เว็บ
   (ตอนทดสอบในเครื่องใช้ `http://localhost:5173`)
5. ไปที่ **Project Settings → API** คัดลอก Project URL และ anon (publishable) key ไปใส่ใน `web/config.js`
   ห้ามใช้ service_role / secret key ในหน้าเว็บ
6. เปิดเว็บในเครื่อง:
   ```bash
   npm run web -- -l 5173
   ```

### ตั้งแอดมินคนแรก

แอดมินคนแรกต้องตั้งผ่าน SQL Editor ครั้งเดียว หลังจากนั้นแอดมินให้บทบาทคนอื่นผ่านหน้าเว็บได้

```sql
-- 1) ลงทะเบียนตัวเองเป็นสมาชิก
insert into members (student_id, full_name, email) values ('รหัสนิสิต', 'ชื่อ-นามสกุล', 'อีเมลตัวพิมพ์เล็ก');
-- 2) สมัครผ่านหน้าเว็บด้วยรหัสนิสิต + อีเมลนี้ แล้วกดยืนยันอีเมล
-- 3) ให้บทบาทแอดมิน
insert into user_roles (user_id, role) select user_id, 'admin' from members where student_id = 'รหัสนิสิต';
```

## เอาขึ้น GitHub Pages

GitHub เก็บโค้ดและโฮสต์หน้าเว็บ (`web/`) ส่วนฐานข้อมูล การล็อกอิน และสลิปอยู่ที่ Supabase

1. สร้าง repository ใหม่บน github.com ด้วยบัญชีของรุ่น (เลือก Private หรือ Public ก็ได้ แต่ Pages ฟรีใช้กับ Public เท่านั้น)
2. push โค้ดขึ้น branch `main`
3. ที่ repo ไปที่ **Settings → Pages → Source** เลือก **GitHub Actions**
4. ทุกครั้งที่ push ระบบจะรัน `npm test` ก่อน ผ่านแล้วจึงขึ้นเว็บที่ `https://<ชื่อบัญชี>.github.io/<ชื่อ repo>/`
5. เอาที่อยู่นี้ไปใส่ใน Supabase → Authentication → URL Configuration (Site URL และ Redirect URLs)

anon key ใน `web/config.js` ขึ้น GitHub แบบสาธารณะได้ เพราะสิทธิ์คุมด้วย RLS แต่ห้ามมี service_role / secret key ใน repo

## ข้อมูลทดสอบ

ใช้ [supabase/seed-test.sql](supabase/seed-test.sql) กับ**โปรเจ็กต์ทดสอบเท่านั้น** ในไฟล์มีขั้นตอนอยู่ด้านบน โดยใช้ Gmail เดียวสมัครได้ 5 บทบาท
(ใช้ `ชื่อ+admin@gmail.com`, `ชื่อ+treasurer@gmail.com` ฯลฯ ซึ่งเข้ากล่องเดียวกัน)

อีเมลยืนยันจากระบบส่งเมลในตัวของ Supabase ส่งได้น้อยมากต่อชั่วโมง ในโปรเจ็กต์ทดสอบให้ปิด **Confirm email** ชั่วคราวได้
แต่ในโปรเจ็กต์ใช้จริงต้องเปิดไว้ และควรตั้ง SMTP ของตัวเองใน Authentication → Emails

## บทบาทและสิทธิ์

| บทบาท | ทำอะไรได้ในตอนนี้ |
| --- | --- |
| สมาชิก | เห็นยอดค้าง สลิป เครดิต และแจ้งเตือนของตัวเอง แจ้งชำระ (จ่ายบางส่วน จ่ายเกิน จ่ายแทนเพื่อน) ยกเลิกสลิปที่ยังไม่ถูกตรวจ ใช้เครดิตตัดยอด |
| เหรัญญิก | ได้รับแจ้งเมื่อมีสลิปใหม่ ตรวจสลิป ยืนยันรับเงินหรือไม่ผ่านพร้อมเหตุผล เห็นสมาชิก ยอดค้าง และสมุดบัญชีทั้งหมด |
| ประธาน | สร้าง/แก้กิจกรรมและรายการเรียกเก็บ เห็นสมุดบัญชี |
| ผู้ตรวจสอบ | ดูได้ทุกอย่างรวมถึงประวัติการกระทำ แก้ไขอะไรไม่ได้ |
| แอดมิน | เพิ่ม/นำเข้า/แก้ไข/ระงับสมาชิก (ระงับต้องมีเหตุผล) ให้บทบาท จัดการบัญชีรับเงินและรายการเรียกเก็บ **ไม่เห็นสลิปและสมุดบัญชี** ถ้าไม่ได้เป็นเหรัญญิกด้วย และให้บทบาทตัวเองไม่ได้ |

กฎที่ฐานข้อมูลบังคับเอง แม้เรียก API ตรงหรือเป็นผู้ดูแลฐานข้อมูล:

- สมัครได้เฉพาะรหัสนิสิต + อีเมลที่ลงทะเบียนไว้ และสมัครซ้ำไม่ได้
- ระงับสมาชิก (`active = false`) แล้วสิทธิ์ทุกบทบาทหายทันที
- ตารางการเงินลบแถวไม่ได้ สมุดบัญชีแก้ยอดไม่ได้ ทำได้แค่ยกเลิกพร้อมเหตุผลครั้งเดียว
- สลิปหนึ่งใบสร้างรายรับที่ยังไม่ถูกยกเลิกได้รายการเดียว
- ประวัติการกระทำบันทึกอัตโนมัติทุกการเพิ่ม/แก้ไข แก้หรือลบไม่ได้
- สลิปเก็บใน bucket ที่ไม่เปิดสาธารณะ รับเฉพาะ JPG/PNG/WEBP ไม่เกิน 5 MB และอัปโหลดแล้วแก้หรือลบไม่ได้

## สำรองข้อมูล

GitHub Actions สำรองให้ทุกวันเวลา 03:00 (เวลาไทย) ทั้งฐานข้อมูล ([.github/workflows/backup.yml](.github/workflows/backup.yml)) และไฟล์สลิปกับใบเสร็จ ([scripts/storage-backup.mjs](scripts/storage-backup.mjs))
ไฟล์สำรองถูก**เข้ารหัส**ก่อนเก็บ เพราะ repo เป็น Public เก็บไว้ 90 วันในหน้า Actions ของแต่ละรอบ

### ตั้งค่าครั้งแรก

ที่ repo → **Settings → Secrets and variables → Actions → New repository secret** เพิ่ม 4 ค่า (อย่าส่งค่าเหล่านี้ให้ใคร):

| ชื่อ | ค่า | หาได้ที่ |
| --- | --- | --- |
| `SUPABASE_DB_URL` | connection string แบบ **Session pooler** (มีรหัสผ่านฐานข้อมูลอยู่ในนั้น) | Supabase → ปุ่ม **Connect** → Session pooler |
| `SUPABASE_URL` | ที่อยู่โปรเจ็กต์ เช่น `https://xxxx.supabase.co` | Project Settings → Data API |
| `SUPABASE_SERVICE_ROLE_KEY` | **secret key** (`sb_secret_...`) หรือ service_role แบบเดิม | Project Settings → API Keys |
| `BACKUP_PASSPHRASE` | รหัสผ่านสำหรับเข้ารหัสไฟล์สำรอง ตั้งเองให้ยาว **และจดเก็บไว้นอก GitHub** ทำหายแล้วเปิดไฟล์สำรองไม่ได้ | ตั้งเอง |

จากนั้นแท็บ **Actions → Backup → Run workflow** เพื่อลองรันทันที ต้องได้เครื่องหมายถูกสีเขียว

ถ้า repo ไม่มีการเปลี่ยนแปลงนาน 60 วัน GitHub จะหยุดงานตั้งเวลาเอง ต้องเข้าไปกดเปิดใหม่ที่แท็บ Actions

### กู้คืน (และทดลองกู้คืน)

1. สร้างโปรเจ็กต์ Supabase **ใหม่ที่ว่างเปล่า** (ห้ามกู้ทับโปรเจ็กต์ที่มีข้อมูล)
2. เพิ่ม Secrets ของโปรเจ็กต์ใหม่: `RESTORE_DB_URL`, `RESTORE_SUPABASE_URL`, `RESTORE_SERVICE_ROLE_KEY` (หาที่เดียวกับตารางข้างบน)
3. แท็บ **Actions → Backup** เปิดรอบที่ต้องการ แล้วจดตัวเลขท้ายลิงก์ (`.../actions/runs/ตัวเลข`)
4. แท็บ **Actions → Restore → Run workflow** ใส่ตัวเลขนั้น และพิมพ์ `กู้คืนลงโปรเจ็กต์ใหม่`
5. ตั้งค่า Authentication (Confirm email, URL Configuration) ของโปรเจ็กต์ใหม่ แล้วเปลี่ยน `web/config.js` ให้ชี้ไปโปรเจ็กต์ใหม่
6. ตรวจว่าล็อกอินได้ ยอดเงินในหน้าสรุปการเงินตรงกับก่อนสำรอง และเปิดสลิปกับใบเสร็จได้

ถอดรหัสไฟล์สำรองเองในเครื่อง (Git Bash):

```bash
openssl enc -d -aes-256-cbc -pbkdf2 -iter 200000 -in r23-backup-XXXX.tar.gz.enc -out backup.tar.gz
```

## เปิดใช้เงินจริง

ทำบนโปรเจ็กต์ Supabase **ใหม่** แยกจากโปรเจ็กต์ทดสอบ (ข้อมูลทดสอบลบไม่ได้):

- [ ] สร้างโปรเจ็กต์ใหม่ด้วยบัญชีของรุ่น รันไฟล์ใน `supabase/migrations/` ตามลำดับ (**ไม่รัน** `seed-test.sql`)
- [ ] Authentication: **เปิด Confirm email**, ตั้ง URL Configuration เป็นที่อยู่เว็บ
- [ ] ตั้ง SMTP ของตัวเอง (Authentication → Emails → SMTP Settings) เพราะระบบส่งเมลในตัวส่งได้น้อยมาก เช่น ใช้บริการส่งเมลฟรีอย่าง Resend หรือ Brevo
- [ ] เปลี่ยน `web/config.js` เป็นที่อยู่และ publishable key ของโปรเจ็กต์จริง แล้ว push
- [ ] ตั้ง Secrets สำหรับสำรองข้อมูลของโปรเจ็กต์จริง รัน Backup หนึ่งครั้ง และ**ทดลองกู้คืน**ลงโปรเจ็กต์ว่างให้สำเร็จหนึ่งครั้ง
- [ ] ตั้งแอดมินคนแรก (ด้านบน) แล้วให้แอดมินอย่างน้อย 2 คน
- [ ] นำเข้ารายชื่อสมาชิก เพิ่มบัญชีรับเงินจริง ให้ตำแหน่งเหรัญญิก ประธาน ผู้ตรวจสอบ
- [ ] เหรัญญิกตั้ง**ยอดยกมา**พร้อมหลักฐานและผู้รับรอง
- [ ] ทดลองกับกลุ่มเล็ก 3–5 คน หนึ่งรอบเก็บเงิน เทียบยอดในระบบกับบัญชีธนาคารให้ตรง ก่อนเปิดให้ทั้งรุ่น
- [ ] แจก [คู่มือสมาชิก](docs/คู่มือสมาชิก.md) และให้ผู้ดูแลอ่าน [คู่มือผู้ดูแล](docs/คู่มือผู้ดูแล.md)
